# 真机使用与接收端调试指南

> 适用于 GPS共享 1.2.0。界面所有文案均为中文。

## 1. 安装

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

或把 APK 拷到设备，用文件管理器点击安装（需允许「安装未知应用」）。

首次使用会依次申请权限，建议全部允许：

| 权限 | 不授权的后果 |
|---|---|
| 精确位置 | 共享端取不到 GPS 数据；接收端无法注入模拟位置 |
| 附近的设备（Android 12+） | 读不到已配对设备、无法建立蓝牙连接 |
| 通知（Android 13+） | 仍可工作，但看不到常驻状态通知，也不能从通知一键停止 |

---

## 2. 角色与传输方式

主页顶部有两个分段控件：

- **角色**：「共享 GPS」（把本机定位发出去）/「接收 GPS」（接收别处的定位）
- **传输方式**（两个角色都可见）：「蓝牙」/「WiFi」

两者都存在设置里，下次打开保持上次的选择。

---

## 3. 共享 GPS · 蓝牙

适用场景：接收端能识别「蓝牙 GPS 外设」时最省事——**接收端零安装**。

### 3.1 模式一：等待被连接（推荐）

适用场景：手机固定放置，由笔记本 / 平板 / 车机主动来连。

1. 手机与对端设备在「系统设置 → 蓝牙」中**互相配对**。
2. 打开本软件，角色选「共享 GPS」，传输方式选「蓝牙」，连接方式选 **「等待被连接」**（默认）。
3. 点中央大按钮 **「开始传输」**。
4. 状态徽标变为「等待设备连接」，顶部通知出现，屏幕可关闭 / 锁屏（传输继续）。
5. 到对端设备上发起连接，选择手机的**串行端口（SPP）**服务。
   - Windows：`设置 → 蓝牙和其他设备 → 更多蓝牙选项 → COM 端口`，确认存在「传出」端口并记下 COM 号。
6. 连上后状态变为「已连接，发送中」，主页开始显示坐标、速度与发送统计。

串口服务信息（可在主页「串口服务信息」卡片直接看到，也可在「设置」里改）：

- 服务名称：`GPS共享`
- SPP UUID：`00001101-0000-1000-8000-00805F9B34FB`

> 若接收端此前是按旧服务名 `GPS蓝牙传输` 配置的，在设置页把服务名改回原值即可。

### 3.2 模式二：主动连接

适用场景：对端设备（如部分车机）只接受连接、不能主动发起。

1. 先在「系统设置 → 蓝牙」中把手机与目标设备配对。
2. 连接方式切换到 **「主动连接」**。
3. 在「已配对设备」列表中点选目标设备（出现 ✓ 表示已选中）。列表为空时点「刷新列表」。
4. 点 **「开始传输」**。

## 4. 共享 GPS · WiFi

适用场景：接收端是 Android 平板 / 车机，且**你想同时共享网络**，或要**一台手机喂多台设备**。

> 与蓝牙最大的差别：**WiFi 没有「蓝牙 GPS 外设」这样的行业标准**，所以接收端必须装本应用（或其它能读 TCP NMEA 并注入模拟位置的程序）。蓝牙零安装，WiFi 要装接收端——这是两者的根本取舍。

### 4.1 发送端（手机）

1. **手动打开热点**：`系统设置 → 个人热点`。应用**无法自己打开带流量共享的热点**（系统限制），这一步必须你来。
2. 打开本软件，角色「共享 GPS」→ 传输方式 **「WiFi」**。
3. 「热点服务信息」卡片会显示检测到的**热点地址**与**端口**（默认 10110）。检测不到热点时卡片会给出引导。
4. 点「开始传输」。接收端连上来后，「在线接收端」列表会出现它们的地址与连接时长。

> 地址通常形如 `192.168.43.1`，各 ROM 可能不同，以卡片显示为准。

### 4.2 接收端（PC 上先验证）

PC 连上手机热点后，用任意 TCP 工具连 `热点地址:端口`：

```bash
nc 192.168.43.1 10110
```

（Windows 无 `nc` 时可用 PuTTY 选 Raw 连接。）预期每秒出现若干行 `$GPGGA…` / `$GPRMC…`；无定位时也有每秒一帧 `$GPZDA` 保活。

### 4.3 多接收端

同一 `IP:端口` 可以被多台设备同时连接——「在线接收端」列表会逐行列出，一份 GPS 喂多台设备。某一台断开只影响它自己，其余照常。

### 4.4 服务发现

发送端每秒向各网卡的广播地址发一个 UDP 信标（默认端口 10111），接收端据此自动列出可用发送端，**免手输 IP**。可在「设置 → WiFi 传输」里关掉广播或改端口。

在 PC 上验证广播是否发出：

```bash
nc -ul 10111
```

预期每秒收到一行 `GPSSHARE/1|<URL编码的设备名>|10110`。

## 5. 接收 GPS

适用场景：把没有 GPS 的平板 / 车机变成有 GPS 的设备，导航 App 直接可用。

### 5.1 ⚠️ 前置条件：模拟位置授权

接收端靠 Android 的**测试位置提供者**注入定位，这要求**接收端设备能在开发者选项里把本应用选上**：

> 设置 → 关于手机 → 连点「版本号」7 次开启开发者选项
> 开发者选项 → 选择模拟位置信息应用 → 选「GPS共享」

**进不去开发者选项的定制车机，这一步走不通。** 未授权时应用不会闪退，会在状态栏提示「未获得模拟位置授权」，但导航 App 看不到位置。

### 5.2 操作步骤

接收端**支持两种方式**，用主页的「传输方式」开关选，和发送端保持一致即可。

#### 方式一：WiFi（手机开热点）

1. 按第 4 节在手机上开好热点并开始 WiFi 传输。
2. 接收端连上该热点。
3. 打开本软件，角色选 **「接收 GPS」**，传输方式选 **「WiFi」**。
4. 「发现的发送端」列表里应出现手机 → **点一下**自动填入地址与端口；
   也可以直接在「手动连接」卡片里填 `地址` + `端口`。
5. 点中央按钮 **「连接」**。

> 记下的地址失效时（热点重启后网段可能变），应用会**自动改用当前默认网关**
> 重试——接收端连在发送端的热点上，网关就是发送端，所以几乎总能连上。

#### 方式二：蓝牙

1. 先在**系统设置 → 蓝牙**里把接收端与发送端手机**配对**。
2. 发送端：角色「共享 GPS」→ 传输方式「蓝牙」→ 连接方式「等待被连接」→ 开始传输。
3. 接收端：角色「接收 GPS」→ 传输方式选 **「蓝牙」**。
4. 「已配对设备」列表里点选发送端手机（出现 ✓）。
5. 点中央按钮 **「连接」**。

> 蓝牙方式的优点：**省电**，且**不会被系统省电策略关掉**（WiFi 热点会）。
> 断线检测也更快——蓝牙栈在链路断开时立刻报错，不用像 TCP 那样等心跳超时。
> 缺点是**不能顺带共享网络**，且只能一对一。

连上后状态变「已连接」，运行数据卡片开始显示经纬度、速度等。选择会被记住，下次自动回填。

### 5.3 验证定位被接管

在接收端上打开任意导航 App（高德 / 百度 / Google Maps），确认能正常定位、位置跟着手机移动。

**卫星数可能显示 0**——这是 Android 平台限制：测试位置提供者不支持 `GnssStatus`，只能注入单点定位。**不是故障。**

同时在接收端本应用的「卫星」页确认：**卫星列表与雷达图正常显示**（数据来自解析到的 `GSV` 语句，不经过系统）。列表里每颗卫星前面会显示**所属星座的国旗与名称**，并按**在用优先、信噪比从高到低**排列——好用的星排在最上面。表头标明了各列含义：

| 列 | 含义 |
|---|---|
| 卫星 | 星座国旗 + 星座名 + 编号（PRN） |
| 仰角 | 离地平线的高度，越接近 90° 越在头顶 |
| 方位 | 从正北顺时针的角度 |
| 信噪比 | 信号强度，越高越好；0 表示还没搜到 |
| 用于定位 | 这颗星是否正参与解算 |

右上角「**只看有信号的**」可以隐藏那些搜到了但还没信号、也没参与定位的卫星；标题会显示「卫星明细（12 / 24）」这样的筛选结果。**雷达图不受筛选影响，始终画全部卫星**。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 蓝牙串口收不到任何数据 | 确认对端连的是**串行端口**服务而不是「拨号网络」；确认两端 UUID 一致 |
| 状态一直停在「等待设备连接」 | 服务器模式必须由**对端主动发起**连接；若对端只能被连，请改用「主动连接」模式 |
| 显示「无定位信号」 | 到室外开阔处等待 GPS 冷启动（1–3 分钟）；确认系统没有开启「仅限省电模式」 |
| 主页数据卡片全是 `--` | 说明还没开始传输或尚未收到定位，属正常 |
| WiFi 方式收不到数据 | 确认接收端连的是**手机热点**；确认端口一致（默认 10110）；手机侧「热点服务信息」卡片显示的热点地址才是对的 |
| 接收端列表里看不到手机 | 确认手机侧传输方式选了 WiFi 且已「开始传输」；确认接收端与手机在同一热点；个别路由器/热点会隔离广播，此时改用手动填 IP |
| 接收端连上了但导航 App 没反应 | 检查**开发者选项 → 选择模拟位置信息应用**是否选中本应用 |
| 导航 App 有位置但卫星数是 0 | 平台限制，见 5.3，不是故障 |
| 想改发送频率、关掉某类语句 | 「设置」页：频率滑块 1–10 Hz；五个语句开关控制输出内容 |
| 想彻底停止 | 主页中央按钮，或通知栏里的「停止传输」动作 |

---

## 7. 停止与省电

点中央按钮或通知里的「停止传输」会立即：停止前台服务 → 关闭链路（蓝牙 socket / TCP 服务端 / 接收端连接）→ 注销定位监听或卸载模拟位置提供者 → 清空运行状态。退出应用同样会停止。

## 8. 日志导出

「日志」页 → 「导出」，文件保存到系统「下载」目录，文件名形如 `GpsBt_20260923_201500.log`。排查连接问题时，把这份日志发给开发者即可。

主页顶部「GPS共享」下面那行小字会**随角色与传输方式变化**（蓝牙串口输出 / 热点 TCP 输出 / 蓝牙接收 / 热点 TCP 接收）。运行数据里的「**在线时长**」是本次连接建立起的时长——一直稳定增长说明链路好，**反复归零说明在掉线重连**，比翻日志直观。接收角色下统计卡片会改成「已接收条数」，用不上的「发送速率」自动隐藏。

日志按类别筛选：**普通**（连接状态变化）、**卫星**（GSV / GSA 语句）、**数据**（GGA / RMC / VTG / ZDA 等）。**收发两端是对称的**——发送端记的是发出去的语句，接收端记的是收到的语句，所以两个角色下这三个筛选都有内容。

## 9. 开机自动开始传输（可选）

1. 「设置」→「开机自启」→ 打开「**开机自动开始传输**」（默认关闭）。
2. 之后每次重启都会**按当前角色**自动开始：共享角色拉起发送端，接收角色拉起接收端，都按上次的传输方式与目标设备。

前置条件未满足时不会静默失败，会推送「开机自动传输未启动」通知并说明原因：

| 通知里的原因 | 处理办法 |
|---|---|
| 未授予定位权限 | 打开软件，授予「精确位置」后再重启 |
| 未授予蓝牙连接权限 | 打开软件，授予「附近的设备」后再重启（仅蓝牙方式需要） |
| 设备没有蓝牙硬件 | 改用 WiFi 传输方式 |
| 蓝牙未开启 | 开机后手动打开蓝牙；应用会先等 60 秒 |
| 未选择要连接的蓝牙设备 | 先在「主动连接」里选一台设备 |

**Android 12 及以上的限制**：系统不允许后台启动的前台服务读取定位，所以开机自启后可能弹出「需要手动开始传输」通知，点其中的「开始传输」即可恢复（此为前台操作，不再受限）。Android 11 及以下可完全自动。

**国产 ROM 额外注意事项**：小米、OPPO、华为等系统可能拦截开机自启，请在
「系统设置 → 应用管理 → GPS共享」中允许「自启动」，并关闭电池优化（允许后台运行）。
