# 真机使用与接收端调试指南

> 适用于 GPS蓝牙传输 1.0.0。界面所有文案均为中文。

## 1. 安装

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

或把 APK 拷到手机，用文件管理器点击安装（需允许「安装未知应用」）。

首次使用会依次申请三个权限，建议全部允许：

| 权限 | 不授权的后果 |
|---|---|
| 精确位置 | 无法取到 GPS 数据，不能开始传输 |
| 附近的设备（Android 12+） | 读不到已配对设备、无法建立蓝牙连接 |
| 通知（Android 13+） | 仍可传输，但看不到常驻状态通知，也不能从通知一键停止 |

## 2. 模式一：等待被连接（推荐）

适用场景：手机固定放置，由笔记本 / 平板 / 车机主动来连。

1. 手机与对端设备在「系统设置 → 蓝牙」中**互相配对**。
2. 打开本软件，主页连接方式选择 **「等待被连接」**（默认）。
3. 点中央大按钮 **「开始传输」**。
4. 状态徽标变为「等待设备连接」，顶部通知出现，屏幕保持可关闭/锁屏（传输继续）。
5. 到对端设备上发起连接，选择手机的**串行端口（SPP）**服务。
   - Windows：`设置 → 蓝牙和其他设备 → 更多蓝牙选项 → COM 端口`，确认存在「传出」端口并记下 COM 号。
6. 连上后状态变为「已连接，发送中」，主页开始显示坐标、速度与发送统计。

串口服务信息（可在主页「串口服务信息」卡片直接看到，也可在「设置」里改）：

- 服务名称：`GPS蓝牙传输`
- SPP UUID：`00001101-0000-1000-8000-00805F9B34FB`

## 3. 模式二：主动连接

适用场景：对端设备（如部分车机）只接受连接、不能主动发起。

1. 先在「系统设置 → 蓝牙」中把手机与目标设备配对。
2. 本软件连接方式切换到 **「主动连接」**。
3. 在「已配对设备」列表中点选目标设备（出现 ✓ 表示已选中）。列表为空时点「刷新列表」。
4. 点 **「开始传输」**。

## 4. Windows 接收端验证

1. 确认手机与电脑已配对，记下电脑侧蓝牙「传出」端口号（如 COM5）：

   ```bash
   mode
   ```

2. 用串口工具打开该端口（RFCOMM 没有真实波特率，任意值即可，数据位 8、停止位 1、无校验）：
   - [PuTTY](https://www.putty.org/)：连接类型选 Serial，填 `COM5`，Speed 任意。
   - 或任意「串口助手」类软件。

3. 手机上点「开始传输」，等对端连上后，串口工具应持续打印类似下面的原始 NMEA 帧：

   ```
   $GPGGA,012345.00,3113.8250,N,12128.4221,E,1,07,1.0,12.5,M,0.0,M,,*4B
   $GPRMC,012345.00,A,3113.8250,N,12128.4221,E,10.0,87.0,260923,,,A*7C
   $GPGSA,A,3,03,14,19,,,,,,,,,,1.2,1.0,0.8*1A
   $GPGSV,2,1,5,03,45,120,42,14,12,300,28,22,70,040,,19,80,200,35*70
   $GPGSV,2,2,5,08,05,010,,*47
   $GPVTG,87.0,T,,10.0,N,18.5,K,A*05
   ```

   > 上面的校验和不用于逐字比对（时间与坐标会变），请以实际输出为准；可把任一句子粘到 NMEA 校验和工具核对末两位。

4. 每条语句以 `$` 开头、`*` 后两位十六进制结尾、以 `\r\n` 换行；一秒发送若干条（默认 1 帧/秒）。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 串口收到不到任何数据 | 确认对端连的是**串行端口**服务而不是「拨号网络」；确认两端 UUID 一致 |
| 状态一直停在「等待设备连接」 | 服务器模式必须由**对端主动发起**连接；若对端只能被连，请改用「主动连接」模式 |
| 显示「无定位信号」 | 到室外开阔处等待 GPS 冷启动（1–3 分钟）；确认系统没有开启「仅限省电模式」 |
| 主页数据卡片全是 `--` | 说明还没开始传输或尚未收到定位，属正常 |
| 连接后马上断开并提示「蓝牙写失败」 | 对端主动断开了链路；重新在服务端/客户端触发一次连接即可 |
| 想改发送频率、关掉某类语句 | 「设置」页：频率滑块 1–10 Hz；五个语句开关控制输出内容 |
| 通知被划掉 | 前台服务通知设为常驻，通常无法划掉；若仍被清掉，传输继续，可回本软件点「停止传输」 |
| 想彻底停止 | 主页「停止传输」按钮，或通知栏里的「停止传输」动作 |

## 6. 停止与省电

点击「停止传输」会立即：停止前台服务 → 关闭蓝牙 socket → 注销 GPS 监听 → 清空运行状态。退出应用同样会停止传输（服务只由「开始传输」按钮启动）。

## 7. 日志导出

「日志」页 → 「导出」，文件保存到系统「下载」目录，文件名形如 `GpsBt_20260923_201500.log`。排查连接问题时，把这份日志发给开发者即可。

## 8. 开机自动开始传输（可选）

1. 「设置」→「开机自启」→ 打开「**开机自动开始传输**」（默认关闭）。
2. 之后每次重启手机都会按上次的连接方式与设备自动开始传输，无需手动操作。

前置条件未满足时不会静默失败，会推送「开机自动传输未启动」通知并说明原因：

| 通知里的原因 | 处理办法 |
|---|---|
| 未授予定位权限 | 打开软件，授予「精确位置」后再重启 |
| 未授予蓝牙连接权限 | 打开软件，授予「附近的设备」后再重启 |
| 设备没有蓝牙硬件 | 该设备无法传输 GPS |
| 蓝牙未开启 | 开机后手动打开蓝牙；应用会先等 60 秒 |
| 未选择要连接的蓝牙设备 | 先在「主动连接」里选一台设备 |

**Android 12 及以上的限制**：系统不允许后台启动的前台服务读取定位，所以开机自启后可能弹出「需要手动开始传输」通知，点其中的「开始传输」即可恢复（此为前台操作，不再受限）。Android 11 及以下可完全自动。

**国产 ROM 额外注意事项**：小米、OPPO、华为等系统可能拦截开机自启，请在
「系统设置 → 应用管理 → GPS蓝牙传输」中允许「自启动」，并关闭电池优化（允许后台运行）。

关闭这个开关后，重启手机不会自动运行。
