# v2.0.0 真机验收清单

> 对应改造设计：[`docs/superpowers/specs/2026-10-22-gps-share-v2-fidelity-design.md`](superpowers/specs/2026-10-22-gps-share-v2-fidelity-design.md)
> 实施计划：[`docs/superpowers/plans/2026-10-22-gps-share-v2-fidelity.md`](superpowers/plans/2026-10-22-gps-share-v2-fidelity.md)
>
> 本机 `adb` 不可用，以下项目**必须在上机时逐条执行**。开发机上跑通的只是
> 189 个纯 JVM 单元用例，真机行为（尤其是延迟毫秒数）一律以这份清单的实测为准。

**准备**：两台设备（一台作发送端，一台作接收端），都装 2.0.0；接收端设备已按
[使用教程](使用教程.md) 在开发者选项里把本应用设为「模拟位置信息应用」。

---

## 一、核心链路

- [ ] 发送端与接收端都是 2.0.0，连接成功，接收端「定位延迟」显示 **0.5～1.5 秒**
- [ ] 接收端「定位精度」与发送端「定位精度」**一致**（不再出现 49.5 m 的截断值）
- [ ] 接收端「数据来源」显示「GPS卫星定位」
- [ ] 接收端导航软件里的位置跟着发送端手机移动，方向与距离都对

## 二、降级与过期

- [ ] 把发送端拿进隧道/室内，10 秒后接收端「数据来源」变为「网络定位」，「定位精度」变成几十～几百米
- [ ] 回到室外后「数据来源」自动变回「GPS卫星定位」
- [ ] 断链后接收端「定位延迟」变成「已过期 N 秒」并**持续增长**（每秒都在走）
- [ ] 拔掉发送端电源，接收端在 20 秒内提示链路断开

## 三、协议与开关

- [ ] 关掉 GSV 语句，接收端延迟**不应**增加 1 秒（v1.6.2 的老毛病）
- [ ] 关掉 RMC 语句，接收端仍能定位，只是位置晚 1 秒发布（宁可晚也要给完整的一份数据）
- [ ] 发送端日志里能看到 `$GPSSHARE` 开头的一帧，`AGE=` 的值与「定位延迟」卡一致
- [ ] 接收端日志里 `$GPSSHARE` 的 `SEQ` 逐次递增（每次新解算 +1）

## 四、失败与时钟

- [ ] 在开发者选项里取消本应用的「模拟位置信息应用」，接收端应明确提示注入失败
- [ ] 把发送端手机时间调偏 5 分钟，两端定位**不应**受影响（验证时钟免疫）
- [ ] 把接收端手机时间也调偏，几分钟后位置仍正常（只有首次时间戳会有偏差）

## 五、混用兼容（可选，但要确认不崩）

- [ ] 1.6.2 发送端 → 2.0.0 接收端：位置正常，精度仍被截断，「数据来源」显示 `--`
- [ ] 2.0.0 发送端 → 1.6.2 接收端：位置正常，旧接收端忽略 `$GPSSHARE`
